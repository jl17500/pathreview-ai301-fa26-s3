# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | The environment record in the repro report, read against the OS and version the issue states and what the repo's bug-report template asks for (see evidence-guide: Environment) | Pass if it names the OS, the app or runtime version tested, and any other version info the template asks for, and these match the issue's target or the difference is called out. Fail if a needed detail is missing or vague ("latest", "my machine"). | required |
| steps-followable | The repro steps in the report, read against the issue's description of the trigger (see evidence-guide: Steps) | Pass if the steps start from a stated starting state and lead in order to the trigger, with no gap a stranger would have to guess. The main path must be re-runnable; a briefly described side variation does not fail it. Fail if there are no steps, or if a step is missing or ambiguous. | required |
| behavior-matches-issue | The output excerpt, log, or screenshot read against the symptom the issue describes (see evidence-guide: Behavior shown) | Pass if the artifact shows the same error text or wrong result the issue describes, OR the report honestly states it could not reproduce, after trying the issue's own scenario and naming how its environment differed from the reporter's. Fail if it shows an adjacent failure, a setup problem, a different error, tests a different feature than the issue, or never says whether the issue's behavior was observed. | required |
| outcome-honest | The outcome the report states, read against the artifacts that back it (see evidence-guide: Honesty) | Pass if the stated outcome is what the artifacts support. An evidenced cannot-reproduce passes. Fail if it claims "reproduced" on a different behavior, or claims more than the evidence shows. | required |
| repo-conventions | The claim and repro comments read against the contribution guide, templates, and AI-use policy in the repo-facts block (see evidence-guide: Comms) | Pass if the comments follow every convention the repo states. If the repo-facts block says AI use must be disclosed in issue comments, or in all contributions, the comments must contain an explicit disclosure (the tool and the extent, or a plain statement that no AI was used). Do not assume no AI was used; a missing disclosure statement fails, however good the rest is. If the disclosure ask is limited to pull requests or code, or the policy states no ask for comments, no disclosure is needed. For template asks, pass if each item is provided or plainly pointed to; running the issue's own script verbatim counts as giving the input and a runnable reproduction. Fail if a required disclosure is missing, a template item is absent, or a stated rule is broken. | required |
| claim-promises-only | The claim comment read against the issue context | Pass if it names this specific issue and promises only an investigation and a report. Describing an investigation already done, including an honest failed attempt, is allowed. Fail if it promises a fix, a PR, or a date, asks to be assigned or for the issue to be reserved, or claims a confirmed reproduction the report does not support. | required |

## Verdict rule

Accept if every `required` check passes. `preferred` checks never change the verdict. An `unclear` grade on a required check counts as fail, so the package is held.
